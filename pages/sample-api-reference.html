Atlas Knowledge API Reference

Create, retrieve, and publish knowledge-base articles with a REST API.

Portfolio demonstration. Atlas Knowledge API is fictional. Its endpoints, data, authentication rules, and limits are illustrative. This sample is not Document360 documentation or a reproduction of employer work. Requests use a reserved example domain and will not reach a working API.

Overview

Version 1 uses HTTPS and JSON. All endpoints return JSON; dates use UTC timestamps. Base URL: https://api.atlasknowledge.example/v1.

MethodEndpointPurpose
POST/articlesCreate a draft
GET/articles/{article_id}Retrieve an article
POST/articles/{article_id}/publishPublish a draft

This sample covers a single-article workflow. Category administration, editing, and pagination are outside its scope.

Authentication

Send Authorization: Bearer <token> on every request. Tokens belong to one workspace. Use articles:write to create drafts, articles:read to retrieve them, and articles:publish to publish. A token with all three scopes can complete the walkthrough.

Keep tokens in a server-side environment variable. Do not embed them in browser code, screenshots, or repositories.

Create an article

POST /articles creates an article in draft status. Send Content-Type: application/json. Requires articles:write.

FieldType / RequiredRules
titlestring / Yes1–200 characters after trimming.
slugstring / Yes1–100 lowercase letters, digits, or hyphens; must start and end with a letter or digit. Unique per workspace and locale.
category_idstring / YesAn existing category ID in the token’s workspace.
body_markdownstring / Yes1–100,000 characters; cannot contain only whitespace.
localestring / NoOnly en and fr are supported. Defaults to en.

Unknown fields are rejected with 422.

Example request

curl --request POST 'https://api.atlasknowledge.example/v1/articles' \
  --header "Authorization: Bearer $ATLAS_API_TOKEN" \
  --header 'Content-Type: application/json' \
  --data '{
    "title": "Reset your password",
    "slug": "reset-your-password",
    "category_id": "cat_getting_started",
    "body_markdown": "## Reset your password\n1. Select **Forgot password** on the sign-in page.\n2. Enter your email address.\n3. Open the reset link sent to your inbox.",
    "locale": "en"
  }'

Response: 201 Created

The Location header contains /v1/articles/art_001. The response body contains the full article object.

{
  "id": "art_001",
  "title": "Reset your password",
  "slug": "reset-your-password",
  "category_id": "cat_getting_started",
  "body_markdown": "## Reset your password\n1. Select **Forgot password** on the sign-in page.\n2. Enter your email address.\n3. Open the reset link sent to your inbox.",
  "locale": "en",
  "status": "draft",
  "public_url": null,
  "created_at": "2026-10-02T08:00:00Z",
  "published_at": null
}

Errors: 401 invalid token; 403 missing scope; 409 duplicate slug; 422 invalid fields or category; 429 rate limit reached.

Retrieve an article

GET /articles/{article_id} requires articles:read. The required path parameter article_id is the ID returned when the article was created. There is no request body.

curl 'https://api.atlasknowledge.example/v1/articles/art_001' \
  --header "Authorization: Bearer $ATLAS_API_TOKEN"

200 OK returns the same article fields as the create response, reflecting its current status. For a published article, status is published, published_at is a UTC timestamp, and public_url is its reader-facing URL.

Errors: 401, 403, 404 (article does not exist in this workspace), or 429.

Publish an article

POST /articles/{article_id}/publish requires articles:publish. The required path parameter is the article ID. Send no request body. Publication is synchronous.

curl --request POST 'https://api.atlasknowledge.example/v1/articles/art_001/publish' \
  --header "Authorization: Bearer $ATLAS_API_TOKEN"

Response: 200 OK

Returns the full article object. All draft content fields are retained; these fields change:

"status": "published",
"public_url": "https://help.atlasknowledge.example/en/reset-your-password",
"published_at": "2026-10-02T08:05:00Z"

Publishing an already published article returns 200 with its existing publication timestamp and URL; it does not republish it.

Errors: 401, 403, 404, or 429.

Errors and retry behaviour

StatusCodeAction
401unauthorizedSupply a valid, unexpired token.
403forbiddenCheck the token’s endpoint scope.
404not_foundCheck the ID and workspace.
409slug_conflictChoose a different slug or use the ID from the existing create response.
422validation_errorCorrect the fields identified in error.details.
429rate_limit_exceededWait for the number of seconds in Retry-After before retrying.
500internal_errorRecord request_id; follow the retry guidance below.

Errors use the following envelope. details is an empty array when no field-level information applies.

{
  "error": {
    "code": "validation_error",
    "message": "The request contains invalid fields.",
    "details": [{"field": "title", "message": "Title is required."}],
    "request_id": "req_001"
  }
}

The fictional limit is 60 requests per minute per token across these endpoints. A 429 response includes Retry-After in whole seconds.

GET and publish requests can be retried after a timeout or 500, using exponential backoff. Create requests do not support idempotency keys. After an ambiguous create timeout, inspect the article list in the workspace UI before resubmitting: the first request may have succeeded. A repeated successful creation payload would produce a slug conflict.
